## Purpose

Impact-sorted queue, polymorphic evidence and resolution panes per flag type, dry-run preview, rules page with simulation, audit page, undo.

## Location

Code:
- `frontend/console/src/routes/review/+page.svelte` (queue and case side by side; filters and the open case live in the URL: `/review?severity=HARD&sort=impact&case=<case_key>`)
- `frontend/console/src/routes/review/rules/+page.svelte` (rules list, simulate, deactivate for admins, create)
- `frontend/console/src/routes/audit/+page.svelte` + `src/lib/components/review/{AuditTimeline.svelte,audit.ts}` (filters in the URL; a case's History link lists the case key and its flag ids)

- `frontend/console/src/lib/components/review/` (`QueueFilters`, `QueueList`, `CaseView`, `CaseHeader`, `FlagConsole`, `EvidencePane` + `GenericEvidence` + `AssetImage`, `ResolutionForm`, `DryRunPanel`, `RuleForm`; logic in `resolution.ts`, `format.ts`, `filters.ts`)

## Interfaces

Provides:
- Review screens; case deep link `/review?case=<case_key percent-encoded>` (used by the viewer's "Open review case")
- `GET /assets/url?uri=` (viewer role; `dcl-assets` only; 15-minute URL)
- `GET /audit?entity_type&entity_id…&actor&action&since&until&cursor&limit` → `{items, next_cursor}` (reviewer role)

Consumes:
- S1 review API (`/review/cases…`, `/review/dry-run`, `/review/rules…`), typed evidence and suggestions, `FlagView.allowed_actions`, `CaseLocation.folder_id`; rule bodies = the resolution without `action` (`set_unit` → `unit_mapping`, `map_columns` → `schema_mapping`), validated by S1
- Live `case` events and the `review_counts` ops counter published by S1 through `backend.api.ws.publish_event`
- Viewer (`/docs/{doc_id}/viewer`)

Behavior notes: Apply stays disabled until every chosen resolution is complete and, for unit and column mappings, a dry-run of the exact current draft (including its rule scope) has succeeded. A folder scope turns one resolution into one operator rule sent with the same `resolve` call. HARD cases older than three working days are highlighted.
